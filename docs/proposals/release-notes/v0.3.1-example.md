# NVIDIA Health Validation v0.3.1

**Proposed replacement text for team review.** The existing release was published October 13, 2026. This example clarifies the release; it does not change shipped artifacts or the published release description. See the [proposal](proposal.md) for the review scope.

This patch updates the container base, Go toolchain and dependencies. The CLI's health-check behavior and verdict schema remain unchanged from toolkit v0.3.0. Go module consumers upgrading from catalog v0.3.0 also receive catalog fixes that were already included in the v0.3.0 CLI.

| Release information | Value |
| --- | --- |
| CLI and container release | `toolkit/v0.3.1` |
| Bundled catalog | `v0.3.1` |
| Catalog required by toolkit Go module | `v0.3.1` |
| Verdict `schema_version` | `0.3` |
| Container image | `ghcr.io/dsx-ai-factory/health-validation:0.3.1` |
| Image platforms | Linux amd64 and arm64 |

## Security and dependencies

- The Ubuntu base moves to `noble-20260911`, updating `libssl3t64` from `3.0.13-0ubuntu3.11` to `3.0.13-0ubuntu3.16` on both image architectures. [#162](https://github.com/dsx-ai-factory/health-validation/pull/162).
- The release is built with Go 1.27.2, previously 1.27.0. The toolkit module's Go directive is also raised to 1.27.2. [#159](https://github.com/dsx-ai-factory/health-validation/pull/159).
- The linked dependencies `golang.org/x/net` and `golang.org/x/sys` move from v0.58.0 to v0.60.0 and from v0.47.0 to v0.48.0, respectively. [#159](https://github.com/dsx-ai-factory/health-validation/pull/159).

## Upgrade implications

**CLI and container users:** No configuration or verdict-schema migration is required from toolkit v0.3.0. The catalog is now identified as final `v0.3.1`; the v0.3.0 CLI reported `v0.3.1-0.20261008220429-a088431d0419`. These versions were confirmed in the [v0.3.0](https://github.com/dsx-ai-factory/health-validation/actions/runs/37855754451) and [v0.3.1](https://github.com/dsx-ai-factory/health-validation/actions/runs/38479758823) release CI metadata.

**Go module consumers:** Toolkit now requires catalog v0.3.1. Compared with catalog v0.3.0, this adds affected-entity population for non-PASS per-entity results through the optional `health.EntityIdentifier` interface and prevents a Fatal NVLink5 Xid occurrence from also producing a Nonfatal message. These fixes were already in the toolkit v0.3.0 CLI source. Consumers selecting catalog v0.3.0 should account for these corrected outputs when upgrading. [Catalog changes](https://github.com/dsx-ai-factory/health-validation/compare/catalog/v0.3.0...catalog/v0.3.1), [#127](https://github.com/dsx-ai-factory/health-validation/pull/127), [#132](https://github.com/dsx-ai-factory/health-validation/pull/132).

## Install and verify

```bash
docker pull ghcr.io/dsx-ai-factory/health-validation:0.3.1
docker run --rm ghcr.io/dsx-ai-factory/health-validation:0.3.1 version --output json
```

Use the [v0.3.1 integration guide](https://github.com/dsx-ai-factory/health-validation/blob/toolkit/v0.3.1/docs/INTEGRATION.md) for actual health-check execution and host access. The command above reports build metadata. Pin this numbered image or a verified digest for deployment; `latest` follows development on `main`.

For an existing Go consumer module, select the component it uses:

```bash
go get github.com/dsx-ai-factory/health-validation/toolkit@v0.3.1
go get github.com/dsx-ai-factory/health-validation/catalog@v0.3.1
```

Coverage remains as described in the [tagged README](https://github.com/dsx-ai-factory/health-validation/blob/toolkit/v0.3.1/README.md#check-catalog): GB200 coverage is validated, and GB300 remains experimental pending equivalent validation. Continue to inspect skipped checks as well as severity.
